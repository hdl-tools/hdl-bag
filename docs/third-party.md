# Third-party RTL

hdl-bag ships a subset of [PULP](https://pulp-platform.org/) RTL in
`src/hdl_bag/rtl/vendor/pulp/`. `bag generate` copies the files a design uses
into `rtl/vendor/pulp/` of the output, with the `LICENSE` of each package
they come from, and adds their include directories to the file list.

[bom.md](bom.md) is the bill of materials: every package, version, commit, file and licence.
It is generated by `scripts/bom.py` from the files' own headers, and a test fails if it is stale.
This page does not repeat what it lists.

The Solderpad Hardware License v0.51 is permissive (Apache-2.0 style). Each
package's `LICENSE` is kept next to its files, and almost every file keeps its
upstream copyright header and is SHL-0.51. Two files in `common_cells` are not:
`assertions.svh` is Apache-2.0 (lowRISC) and `read.sv` is Apache-2.0 WITH SHL-2.1
(EPFL). Neither licence text is beside the file yet; the bill of materials
says so, and #172 tracks adding them.
`src/hdl_bag/rtl/vendor/pulp/index.json` is the machine-readable record of
packages, and for every file the design units it defines and the files it needs.
Its licence field is a constant, so the bill of materials does not rely on it.

## How the tree is made

- `Bender.yml` pins the versions exactly. Each pin is the minimum version the
  dependency asks for, so that no more is vendored than needs to be.
  `tech_cells_generic` is pinned as well, but none of its files are needed.
  `Bender.lock` records the commits.
- `scripts/vendor_pulp.py`, run in the tools image, checks out the lock, takes
  the compile order from `bender script flist-plus`, and copies only the
  transitive closure of the PULP modules BAG's templates instantiate (the
  `ROOTS` list), with the headers they include.
- The `vendor` CI job re-runs the script with `--check` and fails if the
  committed tree differs.
- Never edit files under `rtl/vendor/` by hand. To bump a version, edit
  `Bender.yml`, run `bender update` and the script in the tools image, and
  review the diff.

## Derived muxes

`src/hdl_bag/rtl/vendor/derived/` holds `bag_axi_mux.sv` and `bag_axil_mux.sv`,
which are the PULP `axi_mux` and `axi_lite_mux` modified by `scripts/derive_mux.py`
(renamed, with a fixed-priority option). They keep the SHL-0.51 notice and
upstream copyright, are linted as third-party RTL, and derive from the `axi`
package listed in the bill of materials. The directory has no `LICENSE` of its
own: the `axi` one applies. They are not in `index.json`.

## Lint policy

Vendored files are compiled by every lint tool, so BAG's use of them is
checked. Their **warnings** are counted in a separate "third-party" line and
never fail `bag lint`; **errors** anywhere still fail. Verible, which checks
style only, skips them. Generated and in-house code must still have zero
unwaived findings.

## Formal properties

hdl-bag ships four of [ZipCPU](https://github.com/ZipCPU/wb2axip)'s formal
property files in `src/hdl_bag/formal/vendor/zipcpu/`, unmodified in the package (a generated copy under a
Project > Module prefix carries renamed unit and macro names and says so on its first line): the AXI4-Lite
(`faxil_master.v`, `faxil_slave.v`) and APB (`fapb_master.v`, `fapb_slave.v`)
protocol properties. `bag generate` copies the ones a design needs into
`formal/vendor/zipcpu/` of the output, with the `LICENSE`. The bill of
materials lists them and their commit.

Each file carries ZipCPU's Apache-2.0 header, and the repository's README
licenses it under Apache 2. The repository has no licence text file, so the
vendored `LICENSE` is the standard Apache-2.0 text. The public full-AXI4
property files are deliberately non-functional subsets, so hdl-bag's AXI4
properties are its own. `scripts/vendor_zipcpu.py` fetches the files; the
`vendor` CI job re-runs it with `--check`. Never edit them by hand.

## Python packages

The Python packages hdl-bag installs, including the `sim` extra for `bag sim`,
are listed with their licences in [bom.md](bom.md). They are not copied into
generated output.
